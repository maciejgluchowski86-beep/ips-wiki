# Proof spine

This file is maintained by the Professor.

It is a small current map of the load-bearing claims, estimates, constructions, reductions, or obstructions separating the group from the active target. It is not a bureaucratic checklist and it is not required to predict the final proof.

Revise it whenever the mathematical picture changes.

## Main target

State the current theorem or positive result as precisely as useful.

## Dependency graph or obstruction map

Record the small set of load-bearing items that currently matter.

For each item record, as useful:

- identifier;
- statement or role;
- dependencies;
- status: `verified`, `claimed`, `conditional`, `refuted`, or `open`;
- current owner: Professor, named student lineage, or outside session;
- decisive file pointer; and
- what would change if the item failed.

Use whatever layout best fits the mathematics.

## Current first unresolved edge

Identify the smallest or most informative unresolved part currently controlling progress. If several edges are genuinely independent, say so.

## Mathematically distinct alternative routes

Record only alternatives that are genuinely different enough to change the expected value of the programme.

Do not list every imaginable change of norm, representation, truncation, or decomposition merely because it can be named.

## Routes eliminated

Record routes whose failure would otherwise be expensive to rediscover, with pointers to the argument or counterexample.

## Revision note

When the spine changes materially, say what new mathematical information forced the revision.

Repeated restatement of the same bottleneck in new language is not a spine advance.
